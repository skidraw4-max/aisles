# AIsles Jury 사용자 매뉴얼

**AISLES STUDIO · AIsles Jury**  
가입부터 서비스 연결, 관찰, 화면 심사, 위원 심사, 결과·개선 관리까지 한 번에 따라 하는 실무 안내서

| | |
|---|---|
| **버전** | 1.1 |
| **기준** | 화면 기준 2026.10 (홈 KPI·제품 메뉴·GitHub 연결 반영) |
| **대상** | Jury 작업 공간을 사용하는 서비스 이용자 |

---

## 이 매뉴얼의 범위

서비스 이용자가 **실제 화면**에서 수행하는 기본 흐름과 관리 메뉴를 설명합니다. 화면 심사와 위원 심사의 결과가 서로 다른 근거를 쓰지 않도록, **심사 전 준비 단계**도 함께 안내합니다.

**v1.1에서 추가·보강한 내용**

- 제품 메인 메뉴(홈, 심사 요청, 결과, 서비스, 개선, 감사 이력, 관리)
- **홈** 대시보드(지금 할 일, KPI 카드 클릭 이동, 최근 활동)
- **서비스** 메뉴와 **서비스 접근 권한**의 구분
- **GitHub** 읽기 전용 연결 경로
- **심사 요청** 메뉴와 서비스 화면 내 심사 시작 경로 구분

## 01 시작하기

### 가입과 로그인

처음 사용할 때 계정을 만들고 Jury 작업 공간에 로그인합니다.

**Jury 계정 만들기**

1. 회원가입 화면에서 이메일·비밀번호 입력
2. **계정 만들기** 선택
3. Google 로그인을 쓰는 경우 인증 화면을 끝까지 완료

**작업 공간에 로그인**

1. 이메일·비밀번호 입력 또는 Google 로그인
2. 로그인 후 **조직**과 **역할** 확인

### 조직과 역할

| 상황 | 화면에서 할 일 |
|------|----------------|
| 아직 조직에 속하지 않음 | **조직 만들기** 안내에 따라 새 조직 생성 |
| 이메일 미인증 | 안내 화면에 따라 이메일 인증 완료 |
| 여러 조직에 소속 | 조직 전환기에서 작업할 조직 선택 |

**역할 예시**

- **소유자·관리자**: 멤버·초대·서비스 접근 권한·일부 운영 지표
- **개발자 등**: 서비스 연결·심사·개선 작업(권한에 따라 제한)
- **보기 전용**: 내용 열람 위주(화면에 **보기 전용** 표시)

## 02 기본 구조

Jury는 **제품 메뉴**, **조직 헤더**, **서비스 상세 탭** 세 층으로 나뉩니다.

### 제품 메인 메뉴

로그인 후 상단(또는 좁은 화면에서는 **메뉴** 버튼)에서 이동합니다.

| 메뉴 | 하는 일 |
|------|---------|
| **홈** | 지금 할 일, 요약 숫자, 최근 활동 |
| **심사 요청** | 조직 단위 심사 근거 입력·요청 |
| **결과** | 완료·진행 중 심사 결과 목록 |
| **서비스** | 연결 목록, 서비스 추가, GitHub, **서비스별** 상세 |
| **개선** | 심사에서 나온 개선 작업 |
| **감사 이력** | 사람이 읽기 쉬운 활동 기록 |
| **관리** | 멤버·권한·보안·자동화 등 **관리 허브** |

> **서비스** 메뉴 = 연결·관찰·심사 **작업**  
> **서비스 접근 권한**(헤더·관리) = 누가 어떤 서비스에 접근하는지 **권한 부여**

### 상단 조직 메뉴

| 영역 | 항목 |
|------|------|
| 조직 | 조직 이름·전환 |
| 관리 링크 | 멤버 · **서비스 권한** · 보안 · 초대(권한 있을 때) |
| 사용자 | 현재 사용자 · 역할 · 로그아웃 |

### 서비스 상세 탭

**서비스** 메뉴에서 서비스 이름을 선택하면, 해당 연결 안에서 아래 탭을 사용합니다.

| 탭 | 내용 |
|----|------|
| **개요** | 연결 상태 · 운영 상태 · 다음 할 일 |
| **연결 설정** | URL·읽기 전용 계정·관찰 실행 |
| **관찰 결과** | 수집된 페이지·발견 사항 |
| **화면 심사** | 명암비 · 터치 영역 · 겹침 등 |
| **심사·개선** | 위원 판정·개선 제안 |
| **기록** | 이 서비스의 실행 이력 |

탭 이름 옆 **뱃지**(필요, 건수, 진행 중 등)로 상태를 짧게 확인할 수 있습니다.

## 03 홈 대시보드

**홈**은 로그인 후 작업의 시작점입니다.

### 지금 할 일

조직 상태에 맞춰 **한 가지** 주요 행동과 버튼이 표시됩니다. 예:

- 서비스가 없음 → **서비스 연결하기**
- 연결은 있으나 정상 연결 0개 → **서비스 확인하기**
- 진행 중 심사 있음 → **진행 상황 보기**
- 첫 심사 전 → **새로 심사하기**
- 열린 개선 있음 → **개선 작업 보기**
- 그 외 → **결과 보기**

### 요약 카드(숫자)

네 칸의 숫자는 각각 아래 화면으로 **카드(제목·숫자·설명)를 클릭**하면 이동합니다.

| 카드 | 숫자 의미 | 클릭 시 이동 |
|------|-----------|--------------|
| **연결된 서비스** | 정상 연결(CONNECTED) 개수 | **서비스** 목록 |
| **심사 근거** | 등록된 근거 자료 수 | **심사 요청** |
| **진행 중 심사** | 대기·실행 중 요청 수 | **결과** |
| **개선 작업** | 열린 개선 작업 수 | **개선** |

부가 설명(전체 서비스 수, 완료 결과 건수 등)은 카드 안에 함께 표시됩니다. **「자세히 보기」** 는 카드 아래 접기 영역으로, 출처 통계 등 기술 정보를 펼칠 때 사용합니다(클릭해도 다른 메뉴로 이동하지 않음).

### 최근 결과와 활동

시간·사용자·활동·대상·상태가 표 형태로 표시됩니다. 상세 감사는 **감사 이력** 메뉴에서 더 볼 수 있습니다.

## 04 서비스 준비

심사를 시작하기 전에 **대상 서비스 연결**과 **근거 수집**을 준비합니다.

### 경로 A: 웹 URL + 읽기 전용 관찰

**서비스** → **서비스 추가** 또는 기존 서비스 → **연결 설정** 탭

| 항목 | 안내 |
|------|------|
| 대상 URL | 심사할 사이트 주소 |
| 계정 권한 | **읽기 전용** 권장 |
| 사이트 정보 | 필요 시 선택 입력 |

**관찰 실행**

1. 연결 설정 저장
2. **읽기 전용 계정**으로 관찰 실행
3. 진행: 대기 → 실행 중 → 완료
4. **관찰 결과** 탭에서 URL·페이지·오류 확인
5. 문제 없으면 **화면 심사** 탭으로 이동

> 로그인 정보는 **최소 권한**만 사용하세요. 비밀번호·토큰은 매뉴얼·티켓에 기록하지 마세요.

### 경로 B: GitHub(읽기 전용)

**서비스** 목록 상단 **GitHub 연결** → GitHub App 연결 → 저장소를 **읽기 전용** 범위로 선택

- Jury에서 **연결 해제**해도 GitHub App 자체는 자동으로 제거되지 않을 수 있습니다(화면 안내 확인).
- 저장소 근거 수집·심사는 제공자가 GitHub인 서비스 흐름을 따릅니다.

### 서비스 목록에서 확인할 것

- **연결 중** / **삭제된 연결** 탭으로 목록 전환
- 서비스 이름 클릭 → 해당 서비스 상세(위 6개 탭)
- 접근 권한 변경은 **관리** → **서비스 접근 권한**(또는 헤더 **서비스 권한**)

---

## 05 화면 심사

**읽기 전용 계정** 방식으로 연결된 서비스에서 **화면 심사** 탭을 사용합니다.

### 실행 방법

1. 서비스 상세 → **화면 심사** 탭
2. **화면 심사 시작**(최초) 또는 **새로 심사**(이후) 클릭
3. 완료될 때까지 대기
4. 문제 항목을 페이지·영역별로 확인

### 결과 해석

| 항목 | 확인 내용 |
|------|-----------|
| 상태 | 문제 있음 / 문제 없음 |
| 대표 항목 | 명암비 · 터치 영역 · 겹침 |
| 근거 | 해당 서비스의 **최신 관찰 화면** |

## 06 심사와 개선

### 권장 흐름(서비스 화면)

1. **화면 심사** 완료
2. 같은 서비스 **심사·개선** 탭 또는 화면 심사에서 **「이 결과로 위원 심사하기」** 로 위원 심사 시작
3. **결과** 메뉴에서 판정·근거·개선 제안 확인

### 심사·개선 탭에서 볼 것

| 항목 | 설명 |
|------|------|
| 판정 | 승인 / 수정 필요 / 보류 등 |
| 개선 제안 | 개선안 · 수정 불필요 · 이전 결과 비교 |
| 근거 | 화면 심사 결과 연결 여부 |

### 심사 요청 메뉴(조직 단위)

**심사 요청** 메뉴는 한 화면에서 **심사 근거를 입력**하고 요청하는 경로입니다.

- 분석 항목·승인된 서비스가 준비되어 있을 때 폼이 표시됩니다.
- 입력할 항목이 없으면 **「서비스에서 ‘이 결과로 위원 심사하기’」** 안내와 **서비스**로 이동하는 버튼이 나옵니다.

일반적으로 **서비스 → 화면 심사 → 위원 심사**가 가장 많이 쓰는 경로입니다.

### 심사 전 체크리스트

- [ ] 화면 심사가 먼저 완료되었는가
- [ ] 심사 대상 URL·서비스가 맞는가
- [ ] 최신 화면 심사 결과가 **근거**로 표시되는가
- [ ] **이전 결과 재사용** 안내가 있으면, 새 심사인지 재사용인지 확인했는가

### 결과 해석

판정만 보지 말고 **근거 데이터**와 개선 제안의 **생성 시점**을 함께 확인하세요.  
**「개선 제안 형식 도입 전 결과」** 등이 보이면, 새 심사인지 이전 결과 재사용인지 먼저 확인합니다.

## 07 관리

### 관리 메뉴(허브)

**관리** 메뉴에서 아래 카드로 이동합니다.

| 카드 | 내용 |
|------|------|
| **서비스 접근 권한** | 연결 상태·역할별 서비스 접근 |
| **운영 지표** | 요청 수·완료율·실패·소요 시간(소유자·관리자) |
| **멤버** | 조직 역할과 상태 |
| **초대** | 이메일 초대·대기 |
| **보안** | 인증·조직 보호 |
| **감사 기록** | 활동 기록(**감사 이력** 메뉴와 동일 로그, 진입 경로만 다름) |
| **자동화** | 자동 실행 상태·중단 |

조직 이름·식별자 등은 같은 **관리** 화면 하단에서 확인할 수 있습니다.

### 기록·결과 구분

| 이름 | 위치 | 용도 |
|------|------|------|
| **결과** | 제품 메뉴 | 심사·판정 결과 목록 |
| **기록** | 서비스 상세 탭 | **그 서비스** 실행 이력 |
| **감사 이력** / **감사 기록** | 제품 메뉴 또는 관리 | 조직 전체 활동 감사 |

### 관리 권장사항

1. 소유자·관리자 역할은 **최소 인원**에게만 부여
2. **서비스 접근 권한** 변경 후 실제 접근 화면으로 확인
3. **감사 이력**에서 실패·중복·재사용 여부 확인
4. 외부 사이트 계정은 **읽기 전용**으로 운영

## 08 문제 해결

| 상황 | 먼저 확인 | 다음 조치 |
|------|-----------|-----------|
| **관찰 결과 없음** | 연결 URL·읽기 전용 계정 | 연결 설정 저장 후 관찰 재실행 |
| **화면 심사 탭 없음·비활성** | 읽기 전용 연결 방식인지 | 연결 설정·제공 방식 확인 |
| **화면 심사 탭이 비어 있음** | 진행 상태·로딩 | 잠시 대기 후 새로고침 |
| **위원 심사 실패** | 화면 심사 완료·근거 연결 | **기록**·**감사 이력**에서 실패 시각 확인 후 재시도 |
| **예전 결과가 표시됨** | 이전 결과 재사용 안내 | 최신 화면 심사 후 **새로 심사** |
| **홈 숫자가 0** | **지금 할 일** 안내 | KPI 카드 또는 버튼으로 **서비스**·**심사 요청** 이동 |
| **GitHub 연결 실패** | 권한·한도·오류 문구 | **GitHub 연결** 화면에서 재연결 |
| **관리 메뉴·설정 접근 불가** | 조직 **역할**·서비스 권한 | 소유자에게 권한 요청 |

운영 중 오류가 반복되면 **실패 시각, 서비스 이름, 실행한 탭, 화면 오류 문구**를 기록해 관리자에게 전달하세요. **비밀번호·인증 토큰은 기록·공유하지 않습니다.**
